Where it stands

M0 is essentially done. Nothing downstream of it has started.

The project has spent its first fortnight on one thing and done it thoroughly: deciding exactly what the training and evaluation data is, and building the code that produces it. Forty-five decisions are logged with their reasoning, every parameter has a config entry, the manifests are rebuilt on corrected measurements, and as of today all six splits exist as audio on disk.

The renderer was the schedule risk in this milestone — its cost was the one row in the run-time file marked unknown, and the milestone notes braced for an overnight job. It is now measured: 21,208 trials in 3.2 hours, 63,624 files, 27 GB, 105.4 h of audio — 2.4 h more than the 103.0 h the manifests script, which is the reverb tail A5 appends to every trial — and nothing failed in any split. Not an overnight job, but 2.4× the 83 minutes projected from a 100-trial sample — the sample was too small and too short-tailed to extrapolate from, and the projection should have been quoted with that caveat. The 27 GB figure it predicted was right.

Resumability stopped being an assertion: the val split was already on disk from the day before, and the full run skipped all 200 of its trials and left them untouched.

The honest counterpart has not changed. src/models/, src/eval/ and src/live_model_metric/ are still empty directories. No model exists, and the metric that is the thesis's primary contribution has not been implemented. Those are two separate build efforts and neither has begun.

For the supervisor

What has been built, in plain terms

Six items, no jargon. The task is to pull one chosen voice out of a recording that also contains another person and background noise. This milestone built the data that task will be learned and judged on — not the model.

Reading the codes

Labels like A1, B2 or B9 throughout this report are individual entries in docs/decisions/decisions.md, each dated and written up with its reasoning and what it cost. A1–A6 cover how the audio itself is built — what counts as the clean reference, how loudness is set, how echo tails and clipping are handled. B1–B13 cover the dataset and the evaluation protocol. Any code in this document can be looked up there.

1. Difficulty is a dial, not a rebuild

Every setting that makes the task harder or easier — how loud the interrupting voice is, how echoey the room is, how much the two people talk over each other, how far they sit from the microphone — lives as a range in one configuration file, and each trial draws its own value from that range. Nothing is hardcoded.

On top of that, trials are drawn from one of two regimes: base (60 % of trials) and hard (40 %). Base is a narrower band sitting inside hard, and every trial records which one it came from. So if the model turns out unable to learn the task, the data does not need regenerating — we filter the set to the base trials and the problem gets easier immediately (B12). The 3.2-hour render does not have to be repeated.

2. The shape of the difficulty can be changed, not just its limits

A range on its own says only what is possible, not what is common. Each setting can instead be given a distribution shape — so the same outer limits can be kept while pulling most trials toward the ordinary, average case and leaving the extremes as rare edge cases. For example, switching the loudness difference between the two speakers from an even spread to one concentrated around the typical value takes trials where the interrupting voice is louder than the target from 25 % of the set down to 17 %, without changing the limits at all. This is a one-line change per setting, and it is built so that altering one setting does not disturb the random draws of any other — the same seed still reproduces everything else exactly.

3. We know where this data sits relative to real life

Two people in an ordinary meeting talk over each other perhaps 10–15 % of the time. In our built data it is 27.5 %, measured. That gap is deliberate: the upper limit was set with reference to the published benchmark for this task rather than to everyday conversation, so the set is harder than daily speech by design and the decision is written down rather than discovered later. (Different data, metric and protocol, so our figures are never a like-for-like comparison with that benchmark's published results.) Every setting in the config also carries a note of what the value would be in an ordinary room, as the reference point for the average case — those notes are indicative and flagged as not yet measured; the pilot confirms them.

4. Harder does not always mean less realistic

Worth a moment because it is counter-intuitive. The amount of echo in a room was allowed to go as low as 0.15 seconds, which sounds like the easy end. But in a room of the size we simulate, that little echo implies walls more absorbent than a professional studio — 2.1 % of trials were effectively room-sized anechoic chambers. The unrealistic corner was the easy end, not the difficult one, so raising the floor to 0.25 s made the data more realistic and harder at the same time. Which settings to loosen first, and what realism each one costs, is worked out in docs/data/difficulty-dial.md, including a table translating echo times into recognisable rooms.

5. The commonest real situation was missing, and now is not

Trials are drawn as four kinds: both people talking (50 %), the target talking with nobody interrupting (25 %), the target silent while someone else talks (20 %), and nobody talking at all (5 %). The second of those — one person speaking uninterrupted, which is the most common thing that actually happens — appeared in zero trials before this was fixed (B9). The last two matter because a model must learn to stay silent rather than invent words when the person it is listening for is not speaking.

6. The data is built so a model cannot pass by cheating

This is the part most easily overlooked and hardest to retrofit. Earlier, a model could have scored well without listening to the target at all, because "did two voices overlap?" was effectively the same question as "is the target present?". The four kinds above are now sized so that, given no overlap, the target is present or absent on exactly a coin flip — the shortcut carries no information. Checked by trying to exploit it: speaker identity now predicts presence at chance (0.503, where 0.500 is a coin flip). One cue is not yet at chance — whether the other person is talking still predicts the target's absence at 0.651 — and that is reported openly rather than left out. Alongside this: no speaker appears in both the training and evaluation sets, the noise recordings are drawn from separate pools that are never crossed between training and evaluation, and a second evaluation set is held back untouched.

Underpinning all six: every run records its random seed, its exact configuration, and the code version that produced it, and dependency versions are pinned — including the speech detector, which is version-checked on every run because an unnoticed upgrade would silently move every overlap figure in the thesis. Any number in this report can be traced back to the settings and code that produced it.

This fortnight

What B2 changed, and why it mattered

The generator measured how much people talked by how long their audio files were. A LibriSpeech file is only 86 % speech — mostly a third of a second of silence before the reader starts — so every overlap figure in the dataset was overstated. Voice-activity detection now measures from where speech actually is.

Re-measured after the rebuild, the correction is worth more than it was on the data that motivated it — the per-trial gap between file-boundary and speech overlap grew from 0.070 to 0.111. Reaching a speech target takes more audio than reaching the same file-duration target, so each trial now carries a longer footprint and file boundaries would misread it by further still.

The mislabelling was not uniform, which is why no correction factor could have fixed it: individual trials were wrong by anywhere up to 0.485, so they sat in the wrong reporting bucket. Since the per-condition breakdown is the thesis's central table, that mattered more than the headline average did.

The audio changed too, not just the labels. Real overlap rose from 0.212 to 0.275 because the placement search now aims at speech, so the generator finally delivers the overlap it was always asking for. The leak scoreboard is unchanged, which is the point — the earlier fixes had to survive this.

Also closed this week

The target activity ceiling came down from 0.85 to 0.78, because 0.85 of speech would need 99 % of the window packed with back-to-back audio and the layout needs gaps. Unreachable draws were being silently dropped. Noise beds with speech in them are now rejected at half a second of unbroken voice — background talkers would otherwise be scored as words the model invented.

The renderer

Checked by measurement, not by whether it ran

A renderer's failure mode is audio that is wrong and still plays perfectly. So each level decision was turned into a property and measured on 150 trials across all four trial types, rather than confirmed by listening or by an exit code.

Those properties held on the full run — every split reports zero failures and the file count is exact. But they only cover what was written down as a decision. A mixture can satisfy all six and still be unusable: wrong speaker enrolled, an interferer that is inaudible or overwhelming, a noise bed that swallows the target. That is what the 40-trial by-ear pass was for — measurement first, listening as the check on what measurement was never told to look for.

Done 17 Aug 2026: all 40 sounded correct. Nothing had to be re-rendered. Stated at its true weight, this is a subjective spot check of 40 trials out of 21,208 — 0.19 % of the set, judged by one listener, not a guarantee over the remainder. It is strong enough to rule out a systematic renderer fault, which is what it was for, and it is the reason the audio can now be trusted downstream. The trial ids were not recorded, so the same 40 cannot be re-listened to later.

Three points the specification left open

Interpreted rather than chosen silently, and each recorded. Noise now covers the reverb tail — A2 predates A5, and read together literally the last stretch would be echo over silence, marking where speech ended. Noise-only trials place the bed where an anchor would have put it, so the condition is not identifiable by loudness alone. The enrollment is levelled, which no decision covers. The EQ curve is also the renderer's own choice; its bands are written into every trial so it stays reportable. All four are worth a supervisor's glance.

Risk

Three things that decide whether this lands

No GPU is secured, and M2 needs 40–70 hours of one

The working machine is a four-core laptop with torch.cuda.is_available() == False. Two M0 items exist specifically to defuse this — surveying public streaming-TSE checkpoints, and resolving HPC access — and neither has been done. The checkpoint survey is described in the milestone file as ten minutes of searching that could save weeks, because a usable causal BSRNN checkpoint turns M2 from a training run into a fine-tune. It is the highest-leverage unstarted task in the project.

The primary contribution is scheduled last

The metric is the deliverable that cannot be cut, and it is finished in week 8 with two milestones downstream of it. Any slip in M0–M2 pushes directly into it. The mitigation is that it must be designed on paper by the end of week 6 even though it is not implemented until week 8 — that drafting has not started either.

Turn-taking is rare in the data, by construction

Searching the 108 two-speaker validation trials for the textbook interruption — target speaking alone, interferer cuts in, target yields, listens, resumes — finds only five. The placement search positions the interferer as one contiguous block to hit an overlap target; it does not model turn-taking, so the pattern occurs by accident. Not a defect, but if interruption handling matters to the argument, that is a data-construction gap rather than something more of the current set will supply.

Closed since the last revision: the renderer's cost, which was the third risk here and the only unknown in the run-time file. Measured at 3.2 hours for the full set — 2.4× the projection, and still comfortably inside a working day.

Open question for the supervisor — now with a cost attached

C2 — how hard should the task be? Measured as word error rate on the raw mixture, currently targeting a 60–80 % floor. It sets the difficulty of every trial, and the trials are now rendered. So the earlier note — resolve it before the renderer runs at full scale — has been overtaken: changing the answer no longer costs a decision, it costs a 3.2-hour re-render and 27 GB rewritten. Recoverable, but it is now the one open question with a price on it. The 40-trial listen is done and found nothing wrong, so what remains is the floor and ceiling WER measurement — that is the evidence this question needs.
