The model is trained and beats doing nothing. The three measurements that form this project's main contribution are implemented and tested. Start here

What the project is, without any terminology.

When you speak to a voice assistant and somebody else is talking nearby, the assistant often hears the wrong person. This project builds a filter that sits in front of the assistant and tries to keep only the voice you care about, throwing the other voice away. The filter is given a five-second sample of the person it should listen for, and must work in real time as the audio arrives.

That much is a known problem with known solutions. The novel part of this project is how you judge whether the filter worked. The usual approach is to measure how clean the filtered audio sounds. This project argues that is the wrong test, because what actually matters is whether the assistant understood the right words. Those two things can come apart: audio that sounds worse to a human ear can be easier for a machine to transcribe, and audio that sounds cleaner can be harder, because the filtering process leaves behind its own distortions.

The one-sentence contribution

The contribution is a way of measuring how much of what the target person said a live assistant actually recovered — not a better filter. The filter exists so that there is something to measure.

The measurements

Three numbers, because any one of them alone can be cheated.

The assistant is played some audio and asked to report what it heard. Its answer is then compared against what the target person actually said — which is known exactly, because these recordings are assembled deliberately rather than collected in the wild.

MeasurementThe question it asksWhy it has to exist
Word error rate How many of the target's words came back wrong or missing? The headline number. But it cannot tell you why a word was wrong.
Interferer content rate Did the other person's words sneak through and get reported as if they were the target's? The genuinely new one. A word error rate counts a wrong word the same whether the other speaker leaked through or the machine simply mis-heard. This separates them.
Non-response rate Did the assistant give up and report nothing at all? A filter that outputs pure silence scores perfectly on the measurement above, because nothing leaked. This stops that from being rewarded.

All three are implemented, covered by 51 automated tests, and validated by reproducing a figure measured earlier in the project to the decimal place. Two of them already produce real numbers using ordinary transcription software in place of the live assistant. The third only becomes meaningful once a real assistant is in the loop, because ordinary transcription software is incapable of declining to answer.

Why the second measurement matters, in numbers

On unprocessed audio — two people talking, no filtering — 52 % of recordings hand the assistant at least two of the wrong person's distinctive words. On clean audio it is 0 %, across 230 recordings, with no false alarms at all. And when the target says nothing while the other person talks, the unfiltered figure rises to 100 %. That failure is invisible to a conventional word error rate.

The model

More training data confirmed the diagnosis, and the improvement is real but modest.

Two weeks ago the model was found to be memorising its training examples: it kept improving on recordings it had already seen while getting steadily worse on new ones. The diagnosis was that there was simply not enough training data. That was tested this week by generating two and a half times as much, and the diagnosis was confirmed.

 Before (1,989 recordings)Now (4,976 recordings)
Separation achieved on unseen audio2.14 dB2.58 dB
Improvement over doing nothing0.55 dB0.99 dB
Memorisation gap, at its best point1.24 dB1.08 dB
Training rounds needed to match the old best142

The important row is the second. Doing nothing at all already achieves 1.59 dB, so the fair question is what the filter adds — and that has nearly doubled. The last row says the model now learns in two rounds what previously took fourteen, which is what more data is supposed to buy.

It is still not perfect. The model still eventually starts memorising, just later and from a better peak. It remains limited by how much data is available rather than by its own size, so more data would help again — but two and a half times the data bought only 0.44 dB, so a further doubling would buy less, for roughly five hours of preparation and a 33 GB upload. That is not where the remaining time should go.

How to read that table, and how not to

This is a comparison of resources, not results. The two systems are trained on different data, evaluated by a different metric, and run under a different protocol, so their scores are not comparable and are never presented as such anywhere in this project. The point of the table is narrower: the gap in performance is overwhelmingly explained by roughly forty times less training, a quarter of the model size, and no pretrained starting point — not by the quality of the implementation.

Stated plainly

What has not been done, so it is not mistaken for progress.

The headline measurement Blocker

Not a single measurement has yet been taken with a real live assistant. Every number in this report uses ordinary transcription software as a stand-in. This is the project's actual result and it has not started, because the assistant model has not been chosen.

The model on its own metric In progress

The trained filter has not yet been scored on the three measurements above — only the unfiltered and perfect-audio reference points have. This costs nothing and is running now.

Real recordings Open

All work so far uses deliberately assembled recordings. A smaller set of real meeting audio is planned as a transfer check and has not been touched.

Comparison against another system Open

One existing off-the-shelf filter should be run on this project's own data, so the argument does not rest on a single system.

What happens next

In order, and the first one needs a decision.

  1. Choose the live assistant model — needs sign-off

    This is the only real blocker. The choice is now a one-hour experiment rather than an open argument: each candidate is played clean audio (can it report accurately?), unfiltered audio (can it fail?), and silence (does it stay quiet?). A candidate that cannot do all three cannot be used. Cost is negligible — roughly £20 for the full evaluation.

    One point does need agreement, because it narrows the stated objective: the assistant will be given audio and asked to reply in text rather than speech. The property being measured is how the assistant hears, and nothing in the three measurements depends on it speaking back. Relaxing this widens the field of usable models considerably and removes a component from the measuring instrument. To keep the original claim honest, a small confirmation run on a genuine speech-to-speech model is planned alongside.

  2. Score the trained filter on the three measurements

    Free, needs no assistant, running in the background now. Produces the first result for an actual system rather than just reference points.

  3. Produce the divergence result — the thesis's central claim

    Vary one setting on the existing filter to produce a family of systems, then show that ranking them by conventional audio quality gives a different order than ranking them by what the assistant actually understood. Needs no retraining.

  4. Do not generate more training data

    It would still help, but the return is diminishing and the filter is not the contribution. Recorded as a decision so it is not revisited by reflex.
